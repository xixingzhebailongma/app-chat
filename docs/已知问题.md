## 三、关键已知限制（已实现，但需知晓其边界）

### 3.1 角色权限：前端只隐藏，后端才是安全边界
- 前端按 `role` 隐藏管理员入口，**这只是 UI，不是鉴权**。
- 真实边界在网关后端：`JwtFilter`（`/api/*`）+ `authz::canAccessSpace`（teacher 仅本人绑定空间，否则 403）+ `InternalTokenFilter`（`/internal/*`）+ 教师告警脱敏（`operator_id/operator_name/remark` 置空）。
- **接手方务必确认后端鉴权始终在网关侧生效，不要因为前端隐藏就假定安全。**

### 3.2 设备控制 200 不代表执行成功
- 网关 `/api/miniapp/device/control` 转发边侧 `/api/devices/{type}/{id}/cmd`，**200 仅代表受理/转发成功**。
- 设备**最终状态靠 WS `device_update` 推送**（`/ws` 经网关透传边侧）；`cmd_response` 回执可靠性见 2.3。

### 3.3 告警推送分级与 30 分钟冷却
- **30 分钟冷却：已实现**（`cooldown.default_seconds=1800`，冷却键 `event_type:device_id:user:channel`，
  **每订阅者、每渠道各一次**，防单个人重复轰炸，不是全局只推一次）。
- **分级判据由边侧 Agent 权威判定**，网关只做防御性复核（字段缺省放行、存在且不达标才抑制）。
- 风险：`transition` 精确取值是 `online->offline`（箭头 `->`）；边侧传 `online_to_offline` 等其它值会
  被抑制为 `final_status:skipped`（HTTP 仍 200 不报错），**边侧不检查响应体则告警静默丢失**。
- `device_offline` 与 `peripheral_offline` **共用模板 `tmpl_001`**：一个退订会连带另一个一起失去推送。
- 冷却语义「每订阅者 vs 全局一次」待产品拍板（现状为每订阅者）。

### 3.4 家长绑定（7.8）已知安全/产品风险
- `openid_token` JWT 可重放（TTL 300s、非一次性），confirm 幂等只防重复行、不防 TTL 内重放。
- unbind 无二次验证（破坏性操作，但已按 openid 限权，A 无法解绑 B）。
- 短信验证码存在**枚举 oracle**：400 文案区分「学号不存在 / 手机号不匹配 / 验证码错误」。
- 多副本下短信验证码/频控在**进程内内存**，副本>1 时失效（需迁 Redis）。

### 3.5 角色缓存分叉（已闭环）
- 已修复：`JwtFilter` 每次请求实时查 `user_roles`（60s 缓存 TTL）覆盖 JWT 内嵌 role，角色同步后**无需重新登录**（最多延迟一个缓存窗口）。仅当 `user_roles` 无记录（Go 从未回灌）时回退 JWT/`wechat_bindings.role` 兜底。

### 3.6 运维日志 `/api/miniapp/operation-logs`：有接口无页面，字段已冻结
- **后端已实现、前端 api 已定义，当前无独立页面消费**。7.5 的「查看处理过程 + 操作人」由
  `/api/miniapp/alerts/{id}/timeline` 满足（告警详情页时间线），运维日志接口留给后续独立页。
- 如需独立运维日志页，按 P2 排期；**接口契约已冻结**，字段名以代码 + 前端 api/mock 为准
  （**不是**早期设想的 `items/op_id/note/target_id`）：
  - 鉴权：admin only（非 admin 403），与 `/alerts/{id}/timeline` 一致。
  - 过滤：`space_id` / `op_type` / `user_id` / `from` / `to`（ISO 时间范围）。
  - 分页：`page`（1..10000）/ `page_size`（1..200，默认 50）；响应键 `logs`（**不是 `items`**）
    + `total` + `page` + `page_size` + `has_more`。
  - 字段：`id`（**不是 `op_id`**）/ `op_type` / `user_id` / `operator_name` / `space_id` /
    `scene_id` / `success_count` / `failed_count` / `detail`（JSONB，**不是 `note`**）/
    `created_at`。无独立 `target_id`：目标落在 `space_id` + `scene_id` + `detail` 里
    （`alert_handle` 的 `detail` 含 `alert_id/event_type/status/remark`；`scene_execute` 用 `scene_id`）。
