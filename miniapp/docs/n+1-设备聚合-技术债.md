# N+1 设备聚合 技术债

> 状态：待排期（倾向方案 A，未开工）。
> 范围：miniapp 前端 + wechat-gateway 网关。教师端不受影响，影响面主要是 admin 全局视角。

## ① 现状（两处 N 次 fan-out）

前端要拿「全局 / 跨教室」的设备在线离线数据时，没有一次性接口，只能逐教室各发一次
`GET /api/miniapp/devices?space_id=`。N = 教室数。

1. **首页总览** `src/pages/home/home.vue:172-175`
   ```js
   // load() 内：并行逐教室拉设备 + 告警统计
   const [deviceLists, statsRes] = await Promise.all([
     Promise.all(spaces.map((s) => api.devices(s.space_id))),  // ← N 次
     api.alertStats(),
   ])
   ```
   目的：聚合全局「设备总数 / 在线 / 离线」+ 每个教室的在线数、待处理数。

2. **设备页「全部」视图** `src/pages/devices/devices.vue:297-314`
   ```js
   // fetchDevices()：admin 选「全部」时跨教室拉
   const lists = await Promise.all(rooms.map((s) => api.devices(s.space_id)))  // ← N 次
   ```

### 不受影响

- `src/pages/classroom/classroom.vue`：单教室，1 次 `api.devices(this.current)`。
- `src/pages/records/records.vue`：单次进出记录列表。

## ② 根因（在网关这层）

1. 网关 `GET /api/miniapp/devices` 是**单空间**接口：
   - `wechat-gateway/src/controllers/src/DeviceController.cpp:16` 取 `space_id` 参数。
   - `wechat-gateway/src/services/src/DeviceService.cpp:17-27`：`space_id` 既喂
     `authz::canAccessSpace(role, userId, spaceId, …)` 做空间边界鉴权，又透传给
     go-backend `GET /devices?space_id=`。

2. **go-backend 返回的设备对象不携带 `space_id`**，前端要自己把空间归属塞回去
   （`devices.vue:305` `out.push({ ...d, space_id: s.space_id })`）。所以即便网关开一个
   「省略 space_id 返回全部」的口子，也会丢失空间归属，首页按教室分组直接断掉。

## ③ 候选方案

### 方案 A（倾向）：新增 `GET /api/miniapp/devices/summary`

- 网关新增聚合端点，admin 一次返回每教室的在线/离线汇总，例如：
  ```json
  { "devices": [{ "space_id": "spc_xxx", "online": 12, "offline": 3, "total": 15 }] }
  ```
- `home.vue` 直接消费，删掉 N 次 fan-out；`devices.vue`「全部」视图可复用或另作批量端点。
- **优点**：一次请求、契约清晰、不污染现有 `devices` 单空间语义。
- **代价**：网关要新增聚合逻辑（空间列表 + 逐空间设备数），是否仍需向 go-backend
  逐空间回源，取决于 go-backend 有无批量/汇总能力（待确认）。

### 方案 B：扩展 `GET /api/miniapp/devices` 支持 admin 省略 `space_id`

- admin 省略 `space_id` 时返回全部设备，且设备对象带上 `space_id`；前端一次拉全量 +
  客户端分组。
- **关键依赖**：设备对象要有 `space_id`——要么网关聚合时补（网关需知道每个设备的空间
  归属），要么推动 go-backend 侧补。
- **优点**：复用现有端点。
- **代价**：改变现有 `space_id` 必填语义，鉴权/边界校验要重写，且仍受 go-backend 返回
  结构约束。

### 建议

- 倾向**方案 A**（新增 `GET /api/miniapp/devices/summary`，admin 全局用）。
- 教师端先不动（本来就 1~2 个绑定教室，N 很小）。
- 开工前需确认：go-backend 是否已有「按空间批量返回设备数」或「全量设备带 space_id」
  能力，以决定方案 A 在网关侧是否还需逐空间回源。
