# 教师订阅消息深链 — 手动验证步骤

> 目的：验证教师点订阅消息能正常深链到告警详情页（脱敏摘要、无处理时间线、不 403）。
> 真机点消息依赖微信账号 + 已审核模板，按下面步骤照做即可。

## 前置条件（先逐项确认）

- [ ] 网关已部署两个新端点，且模板 ID 为真实值：
  - `GET /api/miniapp/alerts/{id}`
  - `GET /api/miniapp/notify/templates`
  - prod 下 `MINIAPP_TMPL_*` 环境变量注入真实模板 ID（config.json 里 `tmpl_*` 占位符会拒绝启动）
- [ ] 小程序构建参数：`USE_MOCK=false`、`BASE_URL` 指向网关、（兜底）`VITE_SUBSCRIBE_TMPL_IDS` 与网关一致
- [ ] 至少一个**教师账号**已绑定某教室（`user_spaces`）
- [ ] 真机微信已成功订阅模板（`requestSubscribeMessage` 全部 accept）

---

## 触发告警的两种方式

**方式一（真实）**：让教师绑定教室的综合屏/编解码器真实离线，等边侧 Agent 上报。

**方式二（测试，推荐先跑通）**：直接调内部接口模拟一条 `device_offline`：

```bash
curl -X POST http://127.0.0.1:8080/internal/notify/send \
  -H 'Content-Type: application/json' \
  -H 'X-Internal-Token: dev-internal-token' \
  -d '{
    "event_type": "device_offline",
    "content": "综合屏离线",
    "space_id": "<教师绑定的教室ID>",
    "device_id": "<设备ID>",
    "device_label": "综合屏",
    "transition": "online->offline",
    "event_id": "evt_verify_001"
  }'
```

> `event_id` 每次换一个唯一值；`X-Internal-Token` 与网关配置一致（dev 默认 `dev-internal-token`）。
> 成功后教师和管理员都应收到订阅消息（`device_offline` 规则 = admin + 对应教室教师）。

---

## 场景 A：教师「已登录」点订阅消息（热启动）

1. 教师账号已在真机小程序里登录，且当前不在告警详情页。
2. 触发一条本教室 `device_offline` 告警。
3. 微信收到订阅消息，**点消息**。

**预期**：
- 直接进入 `pages/alerts/detail`，URL 带 `id=<event_id>`。
- 显示告警摘要：事件类型（设备离线）、设备名（综合屏）、教室、状态（待处理）、产生时间。
- **不显示**「处理过程」段落。
- **不弹** 403 / 权限提示，也**不弹**「处理过程仅管理员可见」。

---

## 场景 B：教师「未登录」点订阅消息（冷启动，核心路径）

1. **完全杀掉**小程序进程（不是切后台）。
2. 触发一条本教室告警。
3. 微信点消息 → 冷启动小程序。
4. 此时未登录，会被引导到登录页，输入教师账号密码登录。

**预期**：
- 登录成功后**自动跳回**该告警的详情页（`App.vue` 记 `pendingAlertId` → `login.vue` 登录后消费）。
- 详情页显示脱敏摘要、无「处理过程」、非 403。

---

## 场景 C：教师点「非本教室」告警 → 404 空态

1. 构造/获取一条**不属于该教师**的告警 `id`（如管理员造一条别的教室的告警，把详情链接发给教师点，或用 mock 里 `spc_b7bee44d` 给绑定 `spc_a8acdd5c` 的教师）。
2. 教师打开 `pages/alerts/detail?id=<非本教室告警ID>`。

**预期**：
- 后端返回 404（与「告警不存在」不可区分，不暴露告警是否存在）。
- 前端显示**空态**「告警不存在或已删除」+「返回告警列表」按钮。
- **不弹**通用错误 toast（404 已按空态处理）。

---

## 场景 D：管理员点同一条告警 → 有处理时间线

1. 管理员账号，触发/点同一条告警详情。
2. 点消息或从列表点进详情。

**预期**：
- 显示告警摘要 + **「处理过程」时间线**（含操作人、备注）。
- 若已有人标记处理，时间线里有对应记录。

---

## 模板 ID 拉取（顺带验证）

1. 登录后打开微信开发者工具 Console / 抓包，确认 `GET /api/miniapp/notify/templates` 返回：

```json
{ "template_ids": ["<tid1>", "<tid2>", "<tid3>"] }
```

2. 断网关服务、只留 env 兜底时，`requestSubscribe` 仍能拉起授权（走 `VITE_SUBSCRIBE_TMPL_IDS`）——验证降级。
